# SnowLog PV 設計書

- 作成日: 2026-07-29
- 対象: SnowLog 紹介映像（PV）
- 状態: 設計確定・未実装

## 1. 目的とゴール

SnowLog の価値を 78 秒で伝える紹介映像を Remotion で制作する。

伝えたい中心命題は「個々の機能」ではなく、**撮った滑走動画が練習ログとして積み上がること**。
この価値は時系列でしか伝わらないため、使用フローを追体験させる構成を採る。

配信先は 2 箇所。

| 配信先 | 形式 |
| --- | --- |
| LP（`pr/web`）ヒーロー下 | 自前ホストの MP4（720p）をクリック再生 |
| YouTube | 1080p マスターをアップロード |

App Store の App Preview は対象外（規定が 15〜30 秒・実機収録素材のみのため別物）。

## 2. 決定事項

| 項目 | 決定 | 根拠 |
| --- | --- | --- |
| アスペクト比 | 16:9 / 1920×1080 | LP 埋め込みと YouTube が主戦場 |
| フレームレート | 60fps（Composition） | CG モーションを滑らかにする。素材は 30fps のまま |
| 尺 | 78 秒（4,680 フレーム） | 広告出稿ではないため 1 分超過を許容 |
| 構成 | 1 日の追体験型 | 価値が時系列でしか伝わらないため |
| 言語 | 日本語のみ | 収録ゲレンデ 378 件はすべて日本、主要ターゲットが国内 |
| 音声 | 合成音声ナレーション + BGM + テロップ | 台本の試行を無料にするため合成音声を選択 |
| トーン | 暗色ベースのクール寄り、モーション多め | ユーザー指定 |
| 設置場所 | `pr/pv/`（独立した npm プロジェクト） | `pr/web` の前例に倣う。本体の Expo 依存と混ぜない |

## 3. シーン構成と台本

尺は初期値。実際には `calculateMetadata` がナレーション音声の実尺から再計算する（§6 参照）。

| # | 尺 | フレーム | 映像 | ナレーション | テロップ |
| --- | --- | --- | --- | --- | --- |
| S1 | 0:00–0:07 | 0–420 | 実写滑走。等速〜0.7 倍。グレイン + ビネット | 今日も、いい一本が撮れた。 | — |
| S2 | 0:07–0:14 | 420–840 | **CG**: 滑走サムネのグリッドが 3D パースで無限に流れる | でも、あの日の一本はどこにある。 | 撮った動画は、増えていく。 |
| S3 | 0:14–0:20 | 840–1200 | ロゴをマスクワイプで叩き込む + 雪パーティクル | SnowLog。滑走動画を、練習ログへ。 | 滑走動画を、練習ログへ。 |
| S4 | 0:20–0:31 | 1200–1860 | 一括インポート。デバイスフレームを 3D 回転させながら再生 | まとめて取り込むだけ。GPS から、滑ったゲレンデを自動で推定します。収録は全国 378 ヶ所。 | まとめて取り込む / 378 のゲレンデを収録 |
| S5 | 0:31–0:43 | 1860–2580 | 動画詳細。タグが順にスタッガーで着弾 | 大回り、小回り、コブ。動画に、その日の練習内容を紐づけて残せます。 | 技術・タグ・メモ |
| S6 | 0:43–0:54 | 2580–3240 | カレンダー → 日記へズームスルー | 滑った日をカレンダーでたどれば、天候も、雪質も、あのときの手応えも、そのまま戻ってきます。 | カレンダーと日記 |
| S7 | 0:54–1:05 | 3240–3900 | ダッシュボード。数字カウントアップ + バー伸長 | 一本ずつの記録は、やがてシーズンの手応えになる。 | 滑走日数 / ゲレンデ / テクニック |
| S8 | 1:05–1:12 | 3900–4320 | **CG**: 端末アイコンに情報が閉じる図 | データは端末の中だけ。広告も、課金もありません。 | オフラインファースト |
| S9 | 1:12–1:18 | 4320–4680 | ロゴ + App Store バッジ | SnowLog、App Store で無料配布中。 | iOS 16+ / 無料 |

台本は計 237 文字。日本語の読み上げ速度を 5.5 文字/秒とすると発話は約 43 秒で、
78 秒の枠に対してモーションを見せる「間」が 35 秒残る。

### 構成上の意図

- **アプリを 20 秒目まで出さない。** 冒頭から UI を見せると「またアプリの宣伝」で離脱する。
  実写 → 課題 → ロゴ、と溜めてから本編に入る。
- **ダッシュボードをオチに置く。** 単体では地味な画面だが「続けるとこうなる」を示す唯一の画面。
  終盤に置いて中心命題を回収する。
- **検索と iCloud 対応は扱わない。** §9 参照。

## 4. 素材台帳

原素材は `.temp/`（gitignore 済み）に配置済み。全 8 ファイル、すべて 30fps。

| ファイル | 尺 | 解像度 | 割当 | 加工 |
| --- | --- | --- | --- | --- |
| 滑走動画.MP4 | 7.7s | 1280×720 | S1 / S2 のフレーム抽出元 | 1080p へ 1.5 倍拡大。グレイン + ビネットで質感補正 |
| ホーム→インポート→まとめてインポート.MP4 | 3.1s | 592×1280 | S4 | 連結 1/3 |
| ビデオを選択→読み込みへ.MP4 | 1.7s | 592×1280 | S4 | 連結 2/3 |
| 読み込み→スキー場サジェスト.MP4 | 6.9s | 592×1280 | S4 | 連結 3/3。計 11.7s で枠 11s にほぼ一致 |
| 動画詳細→タイトル、スキー場など入力.MP4 | 16.3s | 592×1280 | S5 | 12s へトリム |
| カレンダー→日付詳細→日記を選択する.MP4 | 4.9s | 592×1280 | S6 | 連結 1/2 |
| 日記を入力.MP4 | 9.1s | 592×1280 | S6 | 連結 2/2。計 14s を 11s へトリム |
| ホーム→ダッシュボードをスクロール.MP4 | 12.4s | 592×1280 | S7 | 12.4s → 枠 11s。微トリム |

加えて `pr/web/src/assets/screenshots/` の静止画 4 枚（ホーム / 動画詳細 / ダッシュボード / カレンダー）を
必要に応じて静止カットに流用する。

### 解像度に関する既知の制約

- 画面収録が 592×1280 と小さい。デバイスフレーム内に収める分には縮小になるため問題ないが、
  **画面の一部に大きく寄る演出は破綻する。** 部分ズームは使わない。
- 滑走動画が 1280×720 のため 1080p キャンバスでは 1.5 倍拡大になる。
  実写は動きが速くモーションブラーが乗るため粗は目立ちにくいが、
  グレインとビネットを重ねて意図的な「フィルム処理」として見せる。
- **スピードランプ（0.3 倍スロー）は行わない。** 30fps 素材を 1/3 に引き伸ばすとカクつきが露骨に出る。
  S1 は等速、もしくは 0.7 倍までに留める。

## 5. プロジェクト構成

```
pr/pv/
├── package.json          Remotion 4.x / React 19 / TypeScript strict
├── remotion.config.ts
├── tsconfig.json
├── public/               staticFile() で参照（gitignore、README のみ追跡）
│   ├── footage/          実写滑走
│   ├── screen/           画面収録
│   ├── shots/            静止画スクショ
│   ├── grid/             S2 用に抽出した静止フレーム
│   └── audio/            narration/s01.wav … s09.wav, bgm.mp3
└── src/
    ├── Root.tsx          Composition 登録（全体 + シーン単体）
    ├── SnowLogPv.tsx     全シーンの Sequence 並び
    ├── script.ts         台本・尺・テロップの単一の情報源
    ├── theme/
    │   ├── colors.ts     Alpine Blue（アプリの colors.ts をミラー）
    │   ├── springs.ts    spring プリセット
    │   └── typography.ts
    ├── scenes/           S01Hook … S09Cta（9 ファイル）
    └── components/
        ├── DeviceFrame.tsx    iPhone 枠 + 画面素材を 3D で保持
        ├── Caption.tsx        テロップ（文字単位スタッガー）
        ├── CountUp.tsx        数値カウントアップ
        ├── FlashCut.tsx       ホワイトフラッシュ転換
        └── SnowParticles.tsx
```

`pr/web` と同じく独立した npm プロジェクトとし、SnowLog 本体（Expo SDK 55）の依存とは混ぜない。

各シーンは props を受け取る純粋なコンポーネントとし、単体でも `<Composition>` に登録する。
1 シーンだけ直すときに 78 秒を通しでプレビューせずに済ませるため。

`theme/colors.ts` はアプリの `src/constants/colors.ts` を **import せずミラー**する。
プロジェクトを跨ぐ import は tsconfig とビルドが複雑になる割に、色定数は滅多に変わらないため割に合わない。
出典コメントを付けて値をコピーする。

## 6. 尺の単一情報源（最重要）

`src/script.ts` にシーン ID・ナレーション音声ファイル・テロップ文字列・最小尺を集約し、
`calculateMetadata` で **ナレーション音声の実尺を読んで各シーンのフレーム数を自動計算**する。

合成音声を採用した以上、台本は必ず何度も録り直す。
尺をシーンごとにハードコードすると、そのたびに 9 ファイルのフレーム数を手で直すことになり、必ずどこかがズレる。
音声ファイルを差し替えるだけで全体が自動で組み直る構造にしておけば、言い回しの試行が無料になる。

参照: `~/.claude/skills/remotion-best-practices/rules/calculate-metadata.md`, `get-audio-duration.md`

## 7. モーションとカラー

- 全編 spring ベース。シーン転換はホワイトフラッシュとブラーワイプ。
- テロップは文字単位のスタッガー出現。
- ユーザー指定により「ややうるさい」程度までモーションを盛る。クール寄りのトーン。
- パレットはアプリの Alpine Blue を踏襲しつつ、PV では背景を暗色側に寄せる。

| 用途 | 値 |
| --- | --- |
| 背景ベース | `alpineBlueDark #0A1929` |
| プライマリ | `alpineBlue #1565C0` |
| 明部・雪 | `glacierWhite #EBF1F7` |
| アクセント | `morningGold #D4A843` |

参照ルール: `animations.md`, `transitions.md`, `text-animations.md`, `3d.md`, `charts.md`, `light-leaks.md`

## 8. 音声・書き出し・配信

### 音声

- ナレーションは **シーン単位で分割**する（`s01.wav` … `s09.wav`）。
  `calculateMetadata` が実尺を読む前提のため、1 本の長尺ファイルにしてはならない。
- BGM はナレーション区間で -12dB 程度にダッキングする。
- 声・BGM とも **商用利用可否とクレジット条件を確認する。**
  VOICEVOX はキャラクターごとに規約が異なる。

### 書き出し

1. `npx remotion render` で 1920×1080 / 60fps / H.264 のマスターを生成
2. マスターから LP 用 720p 版を派生（数 MB に収める）
3. ポスター画像を 1 枚書き出す

### LP への設置

`pr/web/public/` に MP4 を置き、`<video controls poster preload="none">` で表示する。
ナレーション入りのため自動再生はせず、ポスター画像からのクリック再生とする。

**YouTube 埋め込み（iframe）は採用しない。** SnowLog はプライバシーポリシーで
「アナリティクス SDK は組み込まれていません」と明言している。
その LP に YouTube の iframe を置くと訪問者のデータが Google に渡り、掲げている姿勢と食い違う。
YouTube には同じマスターを別途アップロードするに留める。

### リポジトリ運用

- `pr/pv/public/` は `.gitignore` し、`pr/pv/public/README.md` のみ追跡して必要ファイル一覧を記す。
  素材本体は OneDrive 側（`.temp/`）に置く。
- 書き出したマスター MP4 も追跡しない。LP に載せる 720p 版とポスター画像のみ
  `pr/web/public/` に追跡対象として置く。

## 9. スコープ外

- **検索機能の紹介**（旧 S7）。画面収録素材が存在せず、既存スクショにも検索画面がないため削除した。
  LP には記載があるので、PV では扱わない。
- **iCloud 動画対応の紹介。** 78 秒に対して機能が多すぎるため。
- **英語版。** 構造上は後から派生できるが、ナレーション音声の英語収録が別途必要になる。
- **App Store の App Preview。** 規定が異なるため別案件として扱う。
- **9:16 縦版。** 必要になれば Composition を追加して派生させる。
